# مستند پایش، نگهداری و مانیتورینگ پس از راه‌اندازی گیس‌آرا (Post-Launch Monitoring)
## چارچوب ارزیابی مستمر، مهار خطاها و سنجش سئو مدرن در محیط تولید (Production Phase)

این سند رسمی، راهنمای نگهداری و مانیتورینگ پلتفرم تخصصی **گیس‌آرا (GisAra)** پس از راه‌اندازی عمومی (Public Launch) است. این فرآیند بر اصول پایش دیتابیس، سنجش شاخص‌های حیاتی وب (CWV)، پیگیری کوئری‌های هوش مصنوعی (GEO/LLM) و بازیابی سریع سیستم در صورت بروز اختلال استوار است.

---

## ۱. برنامه و فرآیند پشتیبان‌گیری منظم (Backup Strategy)

برای محافظت از زحمات هنرجویان، سوابق خرید و کدهای منحصربه‌فرد گواهی‌نامه‌ها، مکانیزم پشتیبان‌گیری چندلایه زیر در محیط تولید فعال می‌شود:

* **پشتیبان‌گیری دیتابیس لوکال (`db.json`):**
  * **فرکانس:** هر ۱۲ ساعت یک‌بار به صورت کاملاً خودکار.
  * **مکانیزم:** اجرای یک کرون‌جاب (Cron Job) بر روی سرور لینوکس ابری جهت کپی کردن فایل دیتابیس لوکال و ذخیره‌سازی با نام‌های دارای برچسب زمان (Timestamp).
  * **مقصد پشتیبان:** ذخیره در هارد دیسک مجزا از سرور اصلی (مانند درایوهای Object Storage ابری آروان یا کلودفلر) جهت تضمین پایداری در صورت خرابی سخت‌افزار سرور.
* **پشتیبان‌گیری پیکربندی‌ها (.env & sitemap):**
  * پشتیبان‌گیری ماهانه از متغیرهای محیطی لایو و مستندات تنظیمات روتینگ CDN.

---

## ۲. دستورالعمل بازگشت سریع به نسخه پایدار (Rollback Procedure)

در صورت بروز تداخل نرم‌افزاری یا خطای بحرانی بلافاصله پس از آپدیت‌های تولید، فرآیند رول‌بک (بازگشت سریع) به شرح زیر اجرا می‌شود:

1. **مرحله ۱ - توقف موقت ترافیک ناپایدار:**
   * فعال‌سازی حالت نگهداری (Maintenance Mode) در پنل CDN ابر آروان/کلودفلر تا کاربران با پیغام مناسب هدایت شوند.
2. **مرحله ۲ - بازگردانی نسخه بیلد پایدار:**
   * در صورت استفاده از مخزن گیت (Git Version Control)، اجرای سریع دستور بازگشت به کامیت پایدار قبلی:
     ```bash
     git rollback / git checkout <stable_commit_hash>
     npm run build
     npm run start
     ```
3. **مرحله ۳ - بازگردانی پایگاه داده (در صورت خراب شدن ساختار دیتابیس):**
   * جایگزین کردن فایل آسیب‌دیده با آخرین نسخه بک‌آپ سالم از روی Object Storage در آدرس `server/data/db.json`.
4. **مرحله ۴ - تایید پایداری و بازگشایی ترافیک:**
   * اجرای تست دودمانه سریع (Smoke Test) روی صفحه اصلی و صفحات جزئیات، سپس غیرفعال‌سازی حالت نگهداری در CDN.

## ۳. پایش مستمر سئو و ردیابی ارجاعات هوش مصنوعی (AI Overviews & GSC Performance)

سئوی مدرن پس از راه‌اندازی گیس‌آرا در سه بستر مانیتورینگ مورد پایش قرار می‌گیرد:

### ۱. پایش و ردیابی در سرچ کنسول گوگل (First 24 Hours to 30 Days)

* **بازرسی خزیدن (Crawl Budget Audit):**
  * بررسی روزانه بخش **Settings -> Crawl Stats** در سرچ کنسول جهت تایید اینکه ربات‌های گوگل به راحتی صفحات را بدون خطا اسکن می‌کنند.
* **ردیابی ارجاعات هوش مصنوعی (AI Overviews Tracking):**
  * استفاده از فیلترهای نمایش در سرچ کنسول (درگاه **Performance -> Search Appearance**) برای ارزیابی میزان کلیک و نمایش حاصل از پاسخ‌های تولیدشده با هوش مصنوعی گوگل برای کوئری‌های کلیدی شینیون مو.
* **رشد کوئری‌های برندی (Brand Search Volume):**
  * ردیابی روند کلیک کلماتی چون "گیس‌آرا"، "شینیون گیس‌آرا"، "سارا محمدی گیس‌آرا" به عنوان شاخص کلیدی در افزایش اعتبار برند (Entity Authority).

---

## ۴. سنجش مستمر شاخص‌های حیاتی وب (Core Web Vitals Monitoring)

برای حفظ جایگاه ممتاز گیس‌آرا در رده‌بندی‌های سرعت لایو، پایش کارایی سیستم به شکل هفتگی با ابزارهای استاندارد انجام می‌گیرد:

* **TTFB (Time to First Byte):** باید به طور مستمر برای تمامی صفحات در محدوده فوق‌سریع زیر ۵۰ میلی‌ثانیه حفظ شود.
* **LCP (Largest Contentful Paint):** پایش سرعت بارگذاری تصویر اصلی هر شینیون یا بنر اصلی دوره‌ها به نحوی که زیر ۲ ثانیه لود شود.
* **INP (Interaction to Next Paint):** پایش پاسخ‌دهی سریع فیلترها، سبد خرید و منوهای کشویی در موبایل با سرعت پاسخ زیر ۱۰۰ میلی‌ثانیه.
* **CLS (Cumulative Layout Shift):** تضمین صفر بودن میزان جابجایی ناگهانی المان‌ها در هنگام لود کدهای استاتیک و فونت‌های وب.

---

## ۵. فرآیند پایش دوره‌ای و رفع باگ‌های احتمالی (Iterative Maintenance Loop)

چرخه نگهداری مداوم پس از راه‌اندازی به صورت منظم اجرا خواهد شد:

```text
سنجش ورودی‌ها (Measure) ──> تحلیل رفتار خزنده‌ها (Observe) ──> عیب‌یابی مشکلات (Diagnose) ──> اعمال بهبودهای سئو (Improve) ──> تأیید زنده (Validate)
```

* **ممیزی ماهیانه نقشه سایت داینامیک:** بررسی اینکه آیا صفحات پاک شده به درستی از `/sitemap.xml` حذف شده‌اند یا خیر.
* **بررسی هشدارهای امنیتی سرور:** پایش فایل لاگ‌های سرور جهت مهار رفتارهای مشکوک و تلاش برای نفوذهای امنیتی به فرم‌ها.
